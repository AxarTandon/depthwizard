# DepthWizard — From Imagery to Insight

A frontend for turning a single optical remote-sensing image into elevation
information and an interactive 3D terrain model. Built for Smart India
Hackathon 2026.

**This repository is the frontend only.** Height estimation, DSM generation,
SRTM processing, GCP calibration, and any real database or authentication
backend are intentionally out of scope. The app runs entirely in **demo
mode** — no backend, no environment variables, no external service — so it
can be reviewed, deployed, and used standalone.

## Tech stack

- Next.js (App Router) + React + TypeScript
- Tailwind CSS
- Three.js, React Three Fiber, Drei
- Recharts
- Lucide React icons

## Installation

```bash
npm install
```

## Running locally

```bash
npm run dev
```

Visit `http://localhost:3000`. No `.env` file is required — demo mode works
out of the box. `.env.example` documents the variables a future backend
integration would use.

## Demo mode

Every data-producing feature in this app is backed by deterministic, local
logic instead of a real backend:

- **Terrain** — a fixed 128×128 elevation grid generated by
  `lib/terrain.ts`. It uses a seeded noise function plus explicit hills,
  valleys, a ridge line, a flat plateau, and small building-like bumps. The
  same seed is used every time, so the terrain is identical on every
  refresh — it is not random per session.
- **Processing** — `lib/api.ts`'s `getProcessingStatus()` derives a 7-stage
  pipeline's progress from elapsed time only. No machine learning model
  runs anywhere in this codebase.
- **Analysis / Validation** — computed from the same deterministic terrain
  (`lib/calculations.ts`) or from static demo tables
  (`lib/demo-data.ts`). The Validation page is explicitly labeled as demo
  data and should not be read as a real accuracy benchmark.

## Authentication demo

Authentication lives entirely in `lib/auth.ts` and uses `localStorage`:

- `signup()` stores a new user record (demo only — passwords are not
  hashed; this is not production-ready auth).
- `login()` checks credentials against stored users and starts a session.
- `getSession()` / `logout()` manage the active session.
- `/workspace/*` routes are protected by `components/layout/AuthGuard.tsx`,
  which redirects to `/auth/login` if no session is present.

To connect a real backend, replace the internals of the functions in
`lib/auth.ts` (e.g. call a `/login` endpoint and store a JWT) without
changing any other file — every page only imports from this module.

## 3D viewer controls

- **Orbit / pan / zoom** — left-drag to orbit, right-drag to pan, scroll to
  zoom (via OrbitControls).
- **Reset camera** — returns to the default framing.
- **Grid** — toggles a reference ground grid.
- **Wireframe** — toggles the mesh material's wireframe mode.
- **Elevation / Slope / Relative height / Contour** — switches the color
  ramp; slope is computed from neighboring height samples, contours are
  generated with marching squares over the elevation grid.
- **Flythrough** — enables first-person movement: `W`/`A`/`S`/`D` to move,
  `Space` up, `Shift` down, drag to look around. Disables orbit controls
  while active.
- **Measure** — click two points on the terrain to read horizontal
  distance, elevation difference, and 3D distance, with a line drawn
  between them.
- **Terrain query** — click the terrain (outside of measure mode) to read
  elevation, slope, and grid coordinates for that point, sourced from the
  actual demo height matrix.

## Backend integration

`lib/api.ts` exports the functions a backend developer needs to implement:

```
uploadImage(meta)
startReconstruction(projectId)
getProcessingStatus(projectId, elapsedMs)
getTerrainData(projectId)
getProject(projectId)
getProjects()
getAnalysis(projectId)
getValidation()
```

Each function currently resolves with local demo data after a short delay.
Set `NEXT_PUBLIC_USE_BACKEND=true` and `NEXT_PUBLIC_API_BASE_URL` in `.env`,
then replace the body of each function with a real `fetch()` call — the
call sites throughout the app do not need to change, since they only depend
on the exported function signatures and the TypeScript interfaces in
`types/index.ts`.

The expected terrain response shape is:

```ts
{
  project_id: string;
  mode: "rDSM" | "DSM";
  width: number;
  height: number;
  elevations: number[][];
  crs?: string;       // present for DSM
  bounds?: {           // present for DSM
    west: number; south: number; east: number; north: number;
  };
  resolution: number;  // meters per cell
}
```

`crs` and `bounds` are optional for `rDSM` output, since relative height
has no real-world coordinate reference until a backend calibrates it.

## Deployment (Vercel)

This project is a standard Next.js app and deploys to Vercel without any
required environment variables:

```bash
npm run build
```

Push to a Git repository and import it in Vercel, or run `vercel` from the
project root. No database, API keys, or backend service are needed for the
demo to work.

## Limitations

- Elevation output in demo mode is a synthetic, deterministic surface — it
  does not represent a real geographic location.
- A `.tif`/`.tiff` file extension is treated as a signal that GeoTIFF
  metadata *may* be present, not a guarantee. Confirming and calibrating
  real geospatial metadata is backend work.
- Validation metrics are illustrative only and are labeled as such
  throughout the UI.
- Authentication is for demonstration; it is not secure enough for
  production use as written.
